05_GOAL_FRAMEWORK

Purpose

The Goal Framework defines how the system understands, prioritises, and responds to the user’s growth objectives.

The first version of the application is focused specifically on helping content creators grow their accounts.

The system should not attempt to optimise every possible business outcome, such as sales, revenue, or commercial performance.

Its primary purpose is account growth.

⸻

1. Primary Mission

The system’s primary mission is:

Help the user grow as a content creator by making better decisions based on their own performance data, the user’s defined objectives, and the user’s personal strategic algorithm.

The ultimate growth objective may be expressed through different measurable outcomes, including:

* follower growth;
* likes;
* comments;
* saves;
* shares;
* reach;
* engagement;
* or other metrics relevant to account growth.

These metrics may represent intermediate objectives rather than the user’s ultimate goal.

For example:

Ultimate objective: reach 100,000 followers.

Current strategic objective: improve likes.

The system should understand the relationship between the two rather than treating every metric as an independent goal.

⸻

2. Every Action Must Pass Through the Personal Algorithm

A fundamental rule of the system is:

Every meaningful user request or action related to growth should be evaluated through the user’s personal analytical algorithm.

The system should not simply answer a question using generic knowledge.

Instead, it should first consider:

1. the user’s defined objective;
2. the user’s available historical data;
3. the user’s content performance;
4. the user’s personal strategic framework;
5. the patterns identified by the Analytical Engine.

Only after this process should the system formulate its primary response.

This principle applies even when the user asks a seemingly simple question.

The system should consistently preserve the user’s strategic framework rather than gradually replacing it with generic AI recommendations.

⸻

3. User Goal → Algorithm → Recommendation

The intended decision chain is:

User Goal → Personal Algorithm → User Data → Analytical Engine → Relevant Patterns → Recommendation

For example:

The user says:

“I want to grow my followers.”

The system should identify the user’s current situation, analyse the relevant data, and determine what may currently be most useful for achieving that goal.

If the user then says:

“Let’s make a post that increases likes.”

The system should not simply generate a post designed to maximise likes.

It should first run the request through the user’s analytical framework and determine what the user’s own historical data suggests about content capable of producing stronger like performance.

⸻

4. Strategic Flexibility Within the Growth Objective

The system should be capable of identifying intermediate opportunities that may contribute to the user’s broader growth objective.

For example:

The user wants to increase followers.

The system analyses the account and determines that follower growth is not necessarily the only useful area to address immediately.

It may identify that:

* comments are relatively strong;
* likes are comparatively weak;
* saves are strong;
* reach is high but conversion to followers is weak.

The system can then suggest working on the metric or behaviour that appears strategically useful for improving the broader growth objective.

The system should therefore distinguish between:

What the user ultimately wants

and

What may be useful to improve right now.

⸻

5. User Remains in Control

The system may identify opportunities and suggest directions, but it should not automatically impose them on the user.

The user should be able to choose which direction to pursue.

For example:

“Your current data suggests that increasing like activity may be a useful next step for your broader follower-growth objective.”

The user may then choose:

“Yes, let’s work on likes.”

The system then launches the relevant deeper analytical process.

⸻

6. Primary Recommendation vs Additional Knowledge

The system must clearly distinguish between conclusions generated from the user’s personal algorithm and additional information coming from general knowledge.

The primary recommendation should be based on:

* the user’s own data;
* the user’s historical content;
* the user’s goals;
* the user’s personal algorithm;
* and the Analytical Engine.

The system may additionally provide useful information from its broader knowledge base.

For example:

Additional note: this format is currently becoming more popular on the platform and may be worth testing.

This additional information should never be presented as if it were a conclusion derived from the user’s own historical data.

The distinction should remain clear to the user.

⸻

7. Priority of Evidence

When generating recommendations, the system should prioritise evidence in the following general order:

1. The user’s own historical performance data
2. The user’s personal strategic algorithm
3. The user’s current objective and context
4. Relevant external platform knowledge
5. General AI-generated suggestions

External knowledge can enrich the recommendation, but it should not silently override the user’s own evidence.

If external trends contradict the user’s historical data, the system should make that distinction visible rather than presenting one source as unquestionable truth.

⸻

8. Growth as the Common Objective

Different requests may appear unrelated on the surface, but the system should always evaluate them within the broader mission of account growth.

For example:

The user may ask for:

* a Reel idea;
* a carousel;
* a caption;
* a hook;
* a new visual format;
* a strategy for increasing likes;
* an analysis of a previous post.

Each request should ultimately be evaluated through the question:

How can this action contribute to the user’s growth?

The system should therefore preserve strategic continuity between individual content decisions and the user’s broader objective.

⸻

9. Relationship With the Analytical Engine

The Goal Framework defines what the user is trying to achieve.

The Analytical Engine defines how the system analyses the user’s data to help achieve it.

The two components work together:

Goal Framework
→ defines the objective.

Analytical Engine
→ analyses the current situation and relevant historical evidence.

Content Strategy
→ transforms the findings into potential actions.

This separation should be maintained as the application develops.

⸻

10. Core Principle

The central principle of the Goal Framework is:

The system should never lose sight of the user’s ultimate growth objective, even when working on a smaller intermediate metric.

Every recommendation should therefore answer two questions:

What are we trying to improve right now?

and

How can improving this contribute to the user’s broader growth?

This keeps individual content decisions connected to the larger strategy instead of turning the application into a collection of disconnected recommendations.
